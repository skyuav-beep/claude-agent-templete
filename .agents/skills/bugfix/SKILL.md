# Bugfix Skill

> 경로 규칙: `templates/`·`agents/`·`docs/`·`DESIGN.md`는 프로젝트 루트를 먼저 찾고, 없으면 `rules/` 아래 같은 경로를 읽는다.
> 유형 판정이 애매하면 `AGENTS.md ## 작업 유형 선택 규칙`을 먼저 적용한다.

## 절차

1. `templates/bugfix-request.md`를 읽는다.
2. 재현·기대 동작·영향 범위·검증 기준을 정리한다.
3. 최소 재현 범위를 찾고 원인을 확인한다.
4. 승인 후 원인을 좁게 수정하고 회귀 검증을 실행한다.
5. 실패 원인과 남은 위험을 기록한다.

## 입력 처리

- 사용자 메시지에 증상 설명이 있으면 문제 요약을 미리 채운다.
- 설명이 부족하면 "어떤 문제가 발생하는지"부터 묻는다.

## 진행 규칙

- 재현 방법은 환경 → 동작 → 결과 순서로 수집한다.
- 사용자가 재현 방법을 모르면 관찰된 증상만으로 진행한다.
- 검증 기준은 반드시 수집한다.
- 원인이 확인되기 전에 넓은 범위를 고치지 않는다.

## 다른 Skill 연계

- 증상이 시각적이면(레이아웃 깨짐, 색·간격·라운드 불일치, 다크 모드 색 누락) `design` Skill로 연계해 `DESIGN.md` 토큰·alias·Do/Don't 위반을 먼저 점검한다.
- 영향 범위에 UI 컴포넌트나 스타일 파일이 있으면 수정 후 디자인 리뷰를 검증 단계에 포함한다.

## 산출물

구조화된 bugfix-request 블록이 1단계 산출물이다. 원인·수정 범위·회귀 검증 결과를 함께 남긴다.

상세 절차는 `.codex/workflows/bugfix.md`와 `agents/executor-agent.md`를 따른다.
