# Routing Intake Template

## URL 상태 동기화 관리
- 검색어, 탭 활성화 상태, 페이지 번호 등을 URL Query Parameter와 동기화할 것인가?
- 동기화가 필요한 대표적 화면이나 기능

## 접근 제어 (Protected Route)
- 비로그인 유저의 접근 제한 방식
- 다중 권한(예: Admin, 일반 사용자, 매니저 등)에 따른 라우팅 세분화 필요 여부

## 리다이렉트 정책
- 로그인 후 원래 보려던 페이지로 복귀, 잘못된 경로 접근 시 404 처리 등

```
## URL 상태 동기화 관리
- 검색어, 필터, 페이지 번호는 모두 query string으로 동기화.
- 동기화 대상: 주문 목록(`/orders?status=&range=&page=`), 사용자 검색(`/users?q=`).
- query 변경은 `replaceState` 사용. history 누적 방지.

## 접근 제어 (Protected Route)
- 비로그인: `/login`으로 리다이렉트.
- 권한 분기: 일반 사용자, 매니저, 관리자 3등급. 라우트 그룹 단위로 가드.
- 권한 부족: `/403` 페이지로 이동.

## 리다이렉트 정책
- 로그인 성공 시 `?redirect` 쿼리에 적힌 원래 경로로 복귀.
- 미존재 경로: `/404` (커스텀 페이지).
- 슬래시 trailing 정규화: 항상 끝 슬래시 제거.
```
