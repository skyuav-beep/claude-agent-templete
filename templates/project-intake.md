# Project Intake Template

## 프로젝트 한 줄 설명

- 무엇을 만드는지 한 문장으로 적는다.

## 프로젝트 목표

- 이 프로젝트의 가장 중요한 목표는 무엇인가
- 비즈니스 목표 또는 사용자 가치가 무엇인가

## 대상 사용자

- 주요 사용자는 누구인가
- 사용자가 해결하려는 핵심 문제는 무엇인가

## 이번 단계 범위

- 이번에 반드시 포함해야 하는 기능
- 이번 단계에서 제외할 기능
- 나중에 고려할 기능

## 성공 기준

- 어떤 상태가 되면 이번 단계가 성공이라고 볼 수 있는가
- 성능, 완성도, 일정 중 어떤 요소가 더 중요한가

## 제약 사항

- 일정 제약
- 기술 제약
- 수정하면 안 되는 범위

## 미정 사항

- 아직 결정되지 않은 핵심 항목을 적는다.

## 작성 예시

```
## 프로젝트 한 줄 설명
- 헬멧 세척 라이더 매칭 플랫폼의 운영자 대시보드.

## 프로젝트 목표
- 가장 중요한 목표: 신규 라이더의 첫 주문까지 걸리는 시간을 24시간 → 1시간으로 단축.
- 비즈니스 가치: 라이더 풀 회전율 개선, 매장 응대 부담 감소.

## 대상 사용자
- 1차: 본사 운영자 (10명 이내).
- 2차: 매장 매니저 (30개 매장).
- 핵심 문제: 라이더 매칭 현황 파악과 수동 개입이 너무 느리다.

## 이번 단계 범위
- 포함: 주문 목록/상세, 라이더 배차 현황, 수동 재배차, 일별 KPI 카드.
- 제외: 정산, 고객 CS 도구, 모바일 라이더 앱.
- 후순위: 알림 자동화, AI 매칭 추천.

## 성공 기준
- 운영자가 신규 주문을 5분 내 처리 가능.
- 일별 KPI 카드 3종이 정확히 집계.
- 완성도 우선, 속도 다음, 일정은 4주 내 MVP.

## 제약 사항
- 일정: MVP 4주.
- 기술: 사내 표준 Next.js + Supabase 사용.
- 수정 금지: 기존 라이더 앱 API 스키마.

## 미정 사항
- 알림 채널 (Slack vs 자체 푸시).
- 권한 등급 세분화 범위.
```
