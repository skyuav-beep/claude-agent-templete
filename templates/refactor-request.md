# Refactor Request Template

## 리팩터링 목표

- 무엇을 왜 정리하려는지 한 문장으로 적는다.

## 현재 문제

- 중복, 복잡도, 가독성, 구조 문제 등 현재 불편한 점을 적는다.

## 리팩터링 범위

- 수정 대상 파일 또는 모듈
- 건드리면 안 되는 범위

## 유지해야 할 조건

- 바뀌면 안 되는 동작
- 유지해야 할 API 또는 인터페이스
- 성능이나 호환성 관련 조건

## 검증 기준

- 리팩터링 후 어떤 테스트나 확인이 필요한지 적는다.

## 작성 예시

```
## 리팩터링 목표
- `OrderDetail.tsx` 한 파일에 몰린 데이터 페칭/상태/뷰 로직을 분리해 가독성을 회복한다.

## 현재 문제
- 단일 컴포넌트가 480줄로 비대하다.
- 동일한 fetch 로직이 3곳에 중복되어 변경 시 누락 위험이 있다.

## 리팩터링 범위
- `src/features/orders/pages/OrderDetail.tsx`
- 동일 feature 내 hooks 디렉터리 신설 가능
- 다른 feature 파일은 건드리지 않는다.

## 유지해야 할 조건
- 화면에 보이는 동작과 URL은 동일하다.
- 기존 e2e 테스트 `orders/detail.e2e.ts`가 그대로 통과해야 한다.
- 페이지 초기 렌더 성능 저하 없음.

## 검증 기준
- 기존 e2e 테스트 통과
- 단위 테스트로 분리한 hook의 핵심 동작 1건 이상 검증
- 동작 변경 커밋과 구조 변경 커밋을 분리
```
