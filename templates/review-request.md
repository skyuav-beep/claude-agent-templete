# Review Request Template

## 리뷰 대상

- 어떤 파일 또는 변경사항을 리뷰할지 적는다.

## 중점 확인 항목

- 버그 가능성
- 회귀 위험
- 테스트 누락
- 구조 과잉 여부

## 배경 문맥

- 왜 이 변경이 들어갔는지 적는다.

## 원하는 리뷰 결과

- 치명적 문제
- 개선 제안
- 추가 테스트 필요 여부

## 작성 예시

```
## 리뷰 대상
- PR #142: 주문 빠른 필터 추가
- 변경 파일: `src/features/orders/components/OrderListFilter.tsx`, `OrderList.tsx`, 관련 테스트

## 중점 확인 항목
- URL 쿼리 동기화 시 history stack이 비정상적으로 쌓이지 않는가
- 캘린더 필터와 동시 사용 시 충돌 처리가 명확한가
- e2e 테스트가 실제 회귀를 잡는 시나리오인가

## 배경 문맥
- 사용자 문의 누적으로 빠른 필터가 추가되었다. 캘린더 필터는 그대로 유지한다.

## 원하는 리뷰 결과
- 치명적: URL/상태 정합성에 깨질 수 있는 부분
- 개선: 컴포넌트 책임 과다 여부, 네이밍 일관성
- 추가 테스트: 캘린더 + 빠른 필터 동시 조작 시나리오 누락 여부
```
