# 금액·수량 처리 기준

금액과 수량을 **계산·확정·표시·저장**하는 규칙의 정본이다.
시각 표기 규칙(`tabular-nums`, 천 단위 구분자)은 `DESIGN.md`, locale 포맷 API 사용은 `docs/i18n-guidelines.md`를 따른다.
본 문서는 그 앞단, **값 자체를 언제 어떻게 정수로 만드는가**를 다룬다.

## 핵심 원칙

정수화(반올림·절삭)는 **확정 시점에 단 한 번**만 수행한다. 계산 중간과 표시 단계에서는 값을 바꾸지 않는다.

| 계층 | 규칙 | 값 변형 |
|---|---|---|
| 계산 | 전체 정밀도 유지, 라운딩 금지 | 없음 |
| 확정 | 화폐 최소 단위로 정수화 + 잔차 배분 | **여기서만** |
| 표시 | 확정된 값을 포맷만 적용 | 없음 |
| 저장 | 십진 타입 또는 최소 단위 정수 | 없음 |

이 순서를 지키면 사용자가 보는 금액과 실제로 청구·지급되는 금액이 항상 같다.

## 1. 계산 계층

- 중간 계산에서 반올림·반내림·절삭을 하지 않는다. 나눗셈·비율·환율 결과를 그대로 다음 연산에 넘긴다.
- 실수(`float`, `double`, JS `number`) 타입으로 금액을 연산하지 않는다. 라운딩을 하지 않아도 오차가 생긴다.
- 언어별 권장 타입: Java/Kotlin `BigDecimal`, Python `Decimal`, JS/TS 최소 단위 `BigInt` 또는 십진 라이브러리, PHP `BCMath`.
- 나눗셈은 정밀도(유효자리)를 명시해 수행한다. 무한소수에서 예외가 나는 언어가 있다.

## 2. 확정 계층

### 확정 시점의 정의

값이 **외부로 나가거나 원장에 기록되는 순간**이 확정 시점이다.

- 결제 요청·승인 금액, 출금·송금액
- 원장/거래 내역 insert, 정산 확정
- 세금계산서·영수증 발행
- 외부 시스템으로 전달하는 API 응답의 금액 필드

확정 시점은 트랜잭션당 한 번이다. 같은 값을 두 번 정수화하지 않는다.

### 잔차 배분 (largest remainder)

총액을 여러 항목으로 나눌 때, 각 항목을 내림한 뒤 남은 잔차를 **소수부가 큰 항목부터 1단위씩** 배분한다.
항목 합계가 총액과 정확히 일치하게 만드는 표준 기법이다.

```
allocate(total, items):
  floors = [floor(item) for item in items]      # 각 항목 내림
  rest   = total - sum(floors)                  # 남은 잔차 (0 이상, 항목수 미만)
  order  = items를 (item - floor(item)) 내림차순 정렬한 인덱스
           # 소수부가 같으면 항목 ID 오름차순 등 고정 기준으로 tie-break
  for k in 0 .. rest-1:
      floors[order[k]] += 1                     # 소수부 큰 항목부터 1단위씩
  return floors                                 # sum(floors) == total 보장
```

- 적용 대상: 정산금 분배, 할인 금액 안분, 부가세 분리, 쿠폰 분할, 배송비 배분.
- 동률일 때의 순서를 결정론적으로 정한다(항목 ID 오름차순 등). 순서가 흔들리면 재계산 시 결과가 달라진다.
- 배분 결과는 **저장**한다. 화면에서 매번 재계산하면 정렬이 바뀔 때 값이 달라진다.

### 부가세 분리

공급가와 세액 중 **하나를 내림으로 확정하고, 나머지는 총액에서 뺀 값**으로 정한다.
둘 다 독립적으로 정수화하면 합이 총액과 어긋난다.

| 방식 | 공급가 | 부가세 | 합계 |
|---|---|---|---|
| 각각 절삭 | 9,090 | 909 | 9,999 (총액과 1원 차이) |
| 잔차 배분 | 9,090 | 910 | **10,000** |

## 3. 표시 계층

- 표시는 확정된 값을 포맷만 한다. **표시 단계에서 값을 깎지 않는다.**
- 화면에 보인 항목값을 다시 더해서 총액으로 쓰지 않는다. 총액은 확정된 총액을 그대로 표시한다.
- 아직 확정되지 않은 중간값(예상 금액, 실시간 견적)을 보여줄 때는 **어림값임을 카피로 명시**하고, 확정값과 다를 수 있음을 알린다.
- 표시 자릿수는 통화 최소 단위를 따른다(KRW 0자리, USD 2자리). 축약(1.2M) 표기는 좁은 영역에 한정하고, 금액 확인이 목적인 화면에서는 전체 자릿수를 노출한다.

## 4. 저장 계층

- DB 컬럼은 십진 타입(`NUMERIC`/`DECIMAL`)이나 최소 단위 정수(`BIGINT`)를 쓴다. **부동소수 타입(`FLOAT`, `DOUBLE`, `REAL`) 금지.**
- 금액은 **통화 코드와 함께** 저장한다. 숫자만 저장하면 다중 통화 도입 시 해석이 불가능하다.
- 최소 단위 정수 방식을 쓰면 통화별 배수를 명시한다(KRW 1, USD 100, JPY 1, BHD 1000).
- API 경계에서 금액을 실수로 직렬화하지 않는다. 문자열 또는 최소 단위 정수로 전달한다.
- 환율은 적용 시각과 함께 보관한다. 재계산 시 같은 결과가 나와야 한다.

## 통화 최소 단위

| 통화 | 소수 자릿수 | 최소 단위 |
|---|---|---|
| KRW, JPY | 0 | 1 |
| USD, EUR, CNY | 2 | 0.01 |
| BHD, KWD | 3 | 0.001 |

프로젝트가 다루는 통화 목록과 자릿수는 `docs/project-guide.md`에 확정해 적는다.

## 수량 규칙

- 수량은 **단위 정의에 종속**된다. 정수 수량(개, 건, 명)과 소수 수량(kg, L, 시간)을 구분해 정의한다.
- 소수 수량은 허용 소수 자릿수를 단위별로 고정한다. 자릿수를 정하지 않으면 비교·합계가 어긋난다.
- 재고·잔량·잔여 한도는 음수 금지 불변식을 **확정 시점에** 검사한다. 표시 계층 검사는 우회 가능하다.
- `수량 × 단가`는 계산 계층 규칙을 따른다. 수량이 소수면 결과도 정밀도를 유지한 뒤 확정 시점에 정수화한다.
- 수량 상한(1회 주문 최대치 등)은 도메인 규칙이므로 `docs/business-logic-playbook.md` 절차로 정의하고 테스트한다.

## Don't

- 실수 타입으로 금액을 저장하거나 계산한다.
- 계산 중간 단계에서 반올림·절삭한다.
- 표시 단계에서 값을 깎고, 그 값을 다시 계산이나 저장에 사용한다.
- 화면 표시값을 재합산해 총액으로 삼는다.
- 통화 코드 없이 금액 숫자만 저장·전달한다.
- 분배·안분 계산에서 잔차 배분 없이 각 항목을 독립적으로 정수화한다.
- 같은 값을 여러 계층에서 반복 정수화한다.

## 검증 체크리스트

구현·리뷰 시 확인한다.

- [ ] 금액 컬럼과 필드가 십진 타입 또는 최소 단위 정수인가
- [ ] 라운딩이 확정 시점 한 곳에만 있는가 (계산 중간·표시에 흩어져 있지 않은가)
- [ ] 분배·비율·세액 계산에 잔차 배분이 적용됐는가
- [ ] 항목 합계와 총액 일치를 검증하는 테스트가 있는가
- [ ] 표시 로직이 값을 변형하지 않고 포맷만 하는가
- [ ] 금액에 통화 코드가 함께 저장·전달되는가
- [ ] 수량의 허용 소수 자릿수와 음수 금지 조건이 정의·검사되는가

## 근거 (측정값)

본 기준은 다음 검증 결과에 기반한다.

| 검증 | 결과 |
|---|---|
| 중간 절삭 후 계산 vs 정밀도 유지 (단가 3,333.33 × 1,000개) | **330원 차이** — 중간 라운딩이 오차를 누적시킴 |
| 표시만 절삭했을 때 합계-항목 불일치 (무작위 100세트) | **100건 전부 불일치**, 최대 격차 21원 |
| 절삭 표기 vs 반올림 표기 누적 편차 (1,000건) | 절삭 495원(한 방향 누적) / 반올림 5원(상쇄) |
| 잔차 배분 적용 후 항목 합계 | 총액과 **정확히 일치** |
| 실수 타입으로 0.1을 10회 합산 | 0.9999999999999999 — 라운딩 없이도 부정확 |

즉 "표시할 때만 절삭한다"는 접근은 계산 오차 누적은 막지만, 합계-항목 불일치는 해결하지 못한다.
표시 계층에서만 처리하면 **화면 정합성과 금액 정확성 중 하나는 반드시 깨진다.**
정수화를 확정 시점으로 옮기고 잔차를 배분해야 양쪽이 동시에 성립한다.
