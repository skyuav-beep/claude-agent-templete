# 서브 에이전트 가이드

Claude Code의 `Agent` 도구를 사용해 서브 에이전트를 실행하는 방법과 기준을 정리한다.

## 서브 에이전트란

Claude Code는 `Agent` 도구를 통해 독립적인 서브 에이전트를 실행할 수 있다.
서브 에이전트는 별도의 컨텍스트에서 동작하며, 본 에이전트의 컨텍스트를 공유하지 않는다.
따라서 프롬프트에 필요한 배경, 목적, 제약을 명확히 담아야 한다.

## 언제 서브 에이전트를 쓰는가

- 독립적으로 수행 가능한 작업이 병렬로 존재할 때
- 본 에이전트의 컨텍스트 창을 보호해야 할 정도로 결과가 대량일 때
- 역할이 명확히 분리되어 있고, 단계별 검토가 필요할 때

## 언제 서브 에이전트를 쓰지 않는가

- 단순하고 범위가 명확한 작업은 직접 처리한다.
- 서브 에이전트가 이미 수행한 조사를 본 에이전트가 중복으로 수행하지 않는다.
- 결과를 즉시 참조해야 하는 순차 작업은 직접 수행한다.

## 역할별 서브 에이전트

이 저장소의 역할 분리(`agents/`)는 Claude Code 서브 에이전트 타입과 다음과 같이 대응한다.

### general-purpose (기본 범용 에이전트)

- 복잡한 멀티스텝 작업, 코드 검색, 파일 탐색에 사용한다.
- 역할 문서: `agents/main-agent.md`
- 사용 시점: 요청 해석이 필요하거나 전체 작업 흐름을 조율해야 할 때

### Explore (탐색 전용 에이전트)

- 파일 패턴 검색, 키워드 검색, 코드베이스 구조 파악에 특화되어 있다.
- 역할 문서: `agents/researcher-agent.md`
- 사용 시점: 기존 구조 조사, 중복 파일 확인, 근거 수집이 필요할 때
- 탐색 수준: `quick` / `medium` / `very thorough` 중 명시한다.

### Plan (설계 전용 에이전트)

- 구현 계획 수립, 핵심 파일 식별, 아키텍처 검토에 사용한다.
- 역할 문서: `agents/main-agent.md` + `agents/executor-agent.md`
- 사용 시점: 큰 기능 추가나 구조 변경 전 구현 전략을 먼저 정리할 때

## 프롬프트 작성 기준

서브 에이전트는 본 에이전트의 대화 이력을 볼 수 없다.
프롬프트에는 다음을 반드시 포함한다.

- 목적: 무엇을 달성하려 하는가
- 배경: 이미 확인한 것, 제외한 것
- 산출물: 어떤 형태로 결과를 돌려줘야 하는가
- 제약: 수정 금지 파일, 범위 제한, 응답 길이 등

## 병렬 실행 기준

독립적인 작업은 단일 메시지 안에 여러 `Agent` 호출을 묶어 병렬로 실행한다.
순서가 중요하거나 앞 결과가 뒤 작업에 필요한 경우에는 순차 실행한다.

예시:
- 병렬 가능: 두 개의 독립된 파일 조사, 관련 없는 두 영역의 탐색
- 순차 필요: 조사 결과를 반영해야 하는 구현, 구현 후 리뷰

## 결과 처리

- 서브 에이전트의 결과는 본 에이전트가 검토한 뒤 사용자에게 전달한다.
- 서브 에이전트 결과를 그대로 노출하지 않고, 핵심만 요약해서 전달한다.
- 서브 에이전트가 작성한 내용 중 의심스러운 부분은 직접 확인 후 사용한다.
