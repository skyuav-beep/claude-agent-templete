# 에이전트 봇 개발계획 목차

현재 등록된 봇 계획의 탐색용 목차다. 각 계획의 상태와 완료 조건은 연결된 원문이 정본이며, 이 목차가 구현 승인이나 우선순위 변경을 뜻하지 않는다.

## 계획 분류

| 분류 | 계획 | 목적 | 상태 |
|---|---|---|---|
| 지식·개발 공정 관리 | [프로젝트 정리 봇](2026-11-17__development__knowledge-planning-bot.md) | 문서·정책 분류, 목차, TODO·공정 시각화, 기술 스택·구조 설명 | 계획 초안 |
| 에이전트 역량 개선 | [스킬 업데이트 봇](2026-11-17__development__skill-update-bot.md) | 실패 근거 수집, 스킬 개선안, 전후 평가, 검토·반영·복구 | 계획 초안 |

## 함께 읽을 정책·기준

- 문서 분류·명명·생명주기: [지식 관리 가이드](../knowledge-management-guide.md)
- 프로젝트별 확정 기준: [프로젝트 가이드](../project-guide.md) — 템플릿 원본은 scaffold 유지
- 작업 승인·Git 처리: [승인 워크플로](../approval-workflow.md)
- 역할 분담·리뷰·실행 한도: [협업 운영](../claude-codex-collaboration.md)
- TODO·완료 조건·검증 증거: [작업 카드](../../templates/task-card.md)
- 개발 구조·진행 방식: [구조 가이드](../framework-structure-guide.md), [개발 전략](../development-strategy.md)

## 두 봇의 연결과 착수 후보

`프로젝트 정리 봇 → 출처가 있는 반복 실패 사례 → 스킬 업데이트 봇 → 검증된 개선 → 정리 봇의 관련 문서 갱신`

- 정리 봇의 최초 구현 후보: 분류·근거 계약과 수동 호출 목차·TODO 후보 생성.
- 업데이트 봇의 최초 구현 후보: 대상 스킬 1종과 재현·평가 사례 선정.
- 두 봇은 독립적으로 착수할 수 있다. 정리 봇의 문서 ID·출처·기준 버전 계약을 먼저 정하면 이후 근거 전달 형식을 공유하기 쉽다.
- 세션별 실제 다음 작업과 우선순위는 [STATE](../../STATE.md)를 따른다. 자동 갱신·전용 역할·화면 구현은 각 계획의 후속 단계다.
