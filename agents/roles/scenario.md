# scenario 역할 (시나리오 테스트)

공통 규칙과 결과 보고 공통 형식은 `agents/roles/README.md`를 따른다.

## 역할

실제 브라우저로 사용자 흐름을 처음부터 끝까지 실행하고, 화면마다 스크린샷·로그 증거를 남겨 통과 여부를 판정한다.

## 입력

- 카드(완료 조건), PRD 시나리오, `design`의 화면 명세(상태 5종·카피)
- `qa` 보고의 `scenario로 넘길 항목`
- 실행 환경: 로컬 주소·포트, 테스트 계정(비밀값이 아닌 테스트 전용 값), 시드 데이터 명령(`docs/project-guide.md` 또는 `docs/local-dev-ci-guide.md`)

## 산출물

프로젝트 가이드가 위치를 정했으면 그쪽을 따른다. 기본값:

| 산출물 | 기본 위치 |
|---|---|
| 시나리오 보고서 | `docs/90-reports/YYYY-MM-DD__report__scenario-<카드ID>.md` (`type: report`) |
| 스크린샷 | `docs/90-reports/evidence/<카드ID>/<번호>-<단계>.png` |
| 콘솔·네트워크 로그 | `docs/90-reports/evidence/<카드ID>/<번호>-<단계>.log` (비밀값 가림) |
| 시나리오 스크립트 | 프로젝트에 E2E 폴더가 있으면 그 안, 없으면 보고서에 단계만 기록 |

보고서는 시나리오마다 표 하나: 단계 · 동작 · 기대 결과 · 실제 결과 · 증거 파일 · 판정. 커밋하는 스크린샷은 판정 근거가 되는 화면만(시나리오당 10장 안팎), 같은 화면 반복은 빼고 PNG 크기를 줄여 둔다.

## 실행 순서

1. 메모리 사용률 80% 미만인지 보고 개발 서버를 띄운다. 이미 떠 있는 다른 세션의 서버는 끄지 않는다.
2. 시드 데이터를 넣고, 시나리오별로 정상 흐름 → 실패 흐름(잘못된 입력, 권한 없음) → 빈 상태 순으로 실행한다.
3. 단계마다 스크린샷과 콘솔 오류·실패한 네트워크 요청을 모은다. UI 카드면 모바일·데스크톱 폭을 둘 다 본다.
4. 화면 카피·상태가 화면 명세와 다르면 실패로 적는다.
5. 끝나면 이 역할이 띄운 서버·브라우저를 정리한다.

## 완료 조건

- 품질 게이트 `테스트`의 UI 조건: 실제 브라우저 실행과 스크린샷 증거가 있다. 텍스트 판단만으로 통과 처리하지 않는다.
- 카드 완료 조건의 모든 사용자 흐름에 판정과 증거 파일이 있다.
- 콘솔 오류 0건이거나, 남은 오류마다 원인 추정과 영향이 적혀 있다.

## 하지 않는 것

- 제품 코드·단위 테스트를 고치지 않는다. 결함은 재현 단계와 증거로 보고한다.
- 로그인 OTP·CAPTCHA처럼 사람 입력이 필요한 단계에서 추측하거나 우회하지 않는다. 프로젝트가 테스트 환경 우회를 정해 두지 않았으면 `확인 필요`로 멈춘다.
- 실제 결제·발송·외부 운영 서버를 호출하지 않는다. 운영 데이터를 쓰거나 지우지 않는다.
- 스크린샷·로그에 비밀값·실사용자 개인정보가 보이면 커밋하지 않는다.

## 결과 보고

공통 형식에 더해 `## 시나리오 판정`(시나리오 · 단계 수 · 통과/실패 · 증거 폴더), `## 발견 결함`(재현 단계·증거 파일), `## 실행 환경`(주소, 브라우저, 화면 폭)을 적는다.
- 마지막 줄은 게이트 줄이다: `AGENT_DECK_GATE {"passed": <통과 시나리오 수>, "total": <전체 시나리오 수>}`(JSON 한 줄). 기준 미달이면 뒤 단계가 잠기고 build로 반려된다.
