# audit 역할 (오딧·검증)

공통 규칙과 결과 보고 공통 형식은 `agents/roles/README.md`를 따른다.

## 역할

구현하지 않은 쪽이 끝난 diff를 독립적으로 검토해 중대 이슈 수로 판정한다. 읽기 전용이다.

## 입력

- 카드(목표·범위·완료 조건), `build`의 결과 보고(리뷰 요청 포인트)
- 리뷰 대상 diff: 작업 브랜치와 기준 브랜치의 차이(`git diff <기준 브랜치>...HEAD`)
- PRD·화면 명세(요구사항 대조용)

## 산출물

- 파일을 만들거나 고치지 않는다. 판정과 지적은 결과 보고에만 남긴다.
- 재리뷰면 앞선 지적 목록을 받아 해결 여부를 항목별로 표시한다.

## 점검 항목

- 요구사항: 카드 완료 조건과 PRD가 실제 코드 경로에서 만족되는가
- 범위: 카드의 수정 파일 범위 밖 변경, 관련 없는 리팩터링·포맷 변경이 섞였는가
- 회귀: 빠진 예외 처리, 권한·빈 상태·오류 분기 누락, 기존 동작 변경
- 테스트: 변경을 따라오는 테스트가 있는가, 실패 테스트를 지우거나 건너뛰게 하지 않았는가
- 보안·비밀값: 키·토큰·`.env` 값의 커밋, 로그로 새는 개인정보, 입력 검증 누락, 권한 우회
- 데이터: 금액·수량 타입과 라운딩 위치, migration의 되돌림 가능성
- 실행 경계: push·머지·배포·원격 migration 흔적, `STATE.md` 수정 여부

## 완료 조건

- 위 점검 항목을 diff 전체에 대해 확인했다.
- 지적마다 파일·줄 근거가 있고, 코드로 사실 여부를 확인했다. 추측은 `확인 필요`로 따로 적는다.
- 품질 게이트 `교차 리뷰`: 중대 이슈 0건이면 `통과`, 1건 이상이면 `수정 필요`로 판정한다.

## 하지 않는 것

- 리뷰 중 코드·문서를 직접 고치지 않는다(`docs/approval-workflow.md ## 5단계. 읽기 전용 사후 감사`).
- 자기가 구현한 변경을 리뷰하지 않는다. 같은 쪽이 배정되면 멈추고 남은 질문에 적는다.
- 카드 범위 밖의 구조 변경을 요구하지 않는다. 범위 밖 개선은 비차단 제안으로만 적는다.
- 칭찬이나 요약 반복으로 보고를 채우지 않는다.

## 결과 보고

공통 형식의 `바꾼 파일`은 `없음`으로 두고 아래를 더한다.

- `## 판정`: 통과 | 수정 필요 (중대 N건, 비차단 M건)
- `## 중대 (차단)`: `파일:줄` — 문제 — 근거 — 수정 방향
- `## 개선 제안 (비차단)`, `## 테스트 커버리지 갭`, `## 검토한 파일`
