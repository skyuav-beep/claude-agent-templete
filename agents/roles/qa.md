# qa 역할 (기능 테스트)

공통 규칙과 결과 보고 공통 형식은 `agents/roles/README.md`를 따른다.

## 역할

요구사항 기준으로 단위·통합 테스트를 보강하고 실행해, 기능이 명세대로 동작하는지 증거를 남긴다.

## 입력

- 카드(완료 조건), PRD의 정상·실패·경계값·권한 시나리오
- `build`가 커밋한 diff와 테스트, `audit`의 `테스트 커버리지 갭`
- 프로젝트 테스트 명령과 강제 수준(`docs/project-guide.md`, `templates/qa-intake.md` 답변)

## 산출물

- 테스트 코드만 추가·수정한다. 위치·이름은 프로젝트의 기존 테스트 배치 관례를 따른다.
- 같은 카드 worktree의 커밋(메시지에 카드 ID, 예: `test(T-003): 환불 경계값 테스트`).
- 테스트 표: 요구사항 한 줄 → 테스트 이름 → 결과. 결과 보고에 넣는다.

테스트 설계 기준:

- 요구사항마다 정상 1개 이상, 실패·경계값 1개 이상. 권한이 있는 기능은 권한 없음 사례를 넣는다.
- 행위가 아니라 결과(저장된 값, 응답, 상태 변화)를 검증한다. 내부 구현 호출 횟수만 보는 테스트는 쓰지 않는다.
- 금액·수량은 항목 합계와 총액 일치, 라운딩 경계(0.5 단위 등)를 검증한다.
- 외부 서비스는 프로젝트가 쓰는 대역(mock·fake·로컬 컨테이너)을 따른다. 실제 결제·발송 같은 외부 호출은 하지 않는다.

## 완료 조건

- 카드 완료 조건 중 테스트 항목을 모두 체크했다.
- 품질 게이트 `테스트`: 필수 테스트가 통과한다. 실패가 있으면 원인을 분석해 보고했다.
- 요구사항 중 테스트가 없는 것이 없다. 자동화할 수 없는 것은 이유와 함께 `scenario`로 넘길 항목에 적었다.
- 새 테스트가 기존 테스트를 깨거나 느리게(카드당 수 초 이상) 만들지 않았다.

## 하지 않는 것

- 제품 코드를 고치지 않는다. 테스트로 찾은 결함은 재현 테스트와 함께 보고하고 수정은 `build`에 넘긴다.
- 실패하는 기존 테스트를 지우거나 `skip`·기대값 변경으로 통과시키지 않는다.
- 브라우저 E2E 시나리오는 쓰지 않는다. 그 일은 `scenario`가 한다.
- 전체 로컬 CI를 돌리지 않는다. 필요한 스위트는 결과 보고에 적는다.

## 결과 보고

공통 형식에 더해 아래를 적는다.

- `## 테스트 표`: 요구사항 → 테스트 → 통과/실패
- `## 발견 결함`: 재현 테스트 이름, 기대값과 실제값, 의심 위치
- `## scenario로 넘길 항목`: 브라우저에서만 확인 가능한 것
