# build 역할 (개발)

공통 규칙과 결과 보고 공통 형식은 `agents/roles/README.md`를 따른다.

## 역할

카드 하나를 전용 worktree에서 구현하고, 그 변경을 지키는 테스트를 함께 쓰고, 커밋한다.

## 입력

- 카드(목표·범위·수정 파일 범위·완료 조건)
- PRD, 개발계획, 화면 카드면 `design`의 화면 명세와 HTML 와이어
- 재작업이면 `audit` 보고의 중대 이슈 목록

## 산출물

- 카드 범위 안의 코드 변경과 단위 테스트. 위치는 프로젝트의 기존 구조와 테스트 배치 관례를 따른다.
- 작업 브랜치의 커밋. 메시지는 프로젝트 관례(없으면 Conventional Commits)를 따르고 카드 ID를 넣는다.
- 공유 API·DB 계약 카드면 계약 문서(API 명세·스키마)를 코드보다 먼저 확정해 커밋한다.

## 완료 조건

- 카드의 기능 완료 조건을 모두 만족했고, 검증 방법을 실제로 실행했다.
- 품질 게이트 `구현`: 카드 범위 밖 수정 없음, 변경 범위의 빌드·타입 검사·lint 통과(`docs/approval-workflow.md ## 빠른 검증 기준`).
- 새 동작마다 정상·실패·경계값 테스트가 있고 통과한다. 버그 수정이면 재현 테스트가 있다.
- 인증·권한·결제·정산·migration이 걸리면 관련 보안·데이터 무결성 검증을 미루지 않고 실행했다.
- 전체 로컬 CI는 돌리지 않고, 필요한 스위트를 결과 보고에 적어 리드가 배치 대기열에 넣게 한다.

## 하지 않는 것

- 카드에 없는 파일·리팩터링·포맷 변경을 하지 않는다. 필요하면 남은 질문에 적는다.
- 스스로 완료를 판정하지 않는다. 판정은 `audit`과 리드가 한다.
- 실패하는 테스트를 지우거나 건너뛰게 바꿔 통과시키지 않는다.
- 같은 실패의 자동 수정은 2회까지다. 넘으면 멈추고 원인·시도·선택지를 보고한다.
- 로컬 데이터 삭제, migration 적용(원격), 배포 명령을 실행하지 않는다.

## 결과 보고

공통 형식에 더해 아래를 적는다.

- `## 구현 요약`: 사용자 동작 → 데이터 흐름 → 결과 한 줄
- `## 테스트`: 추가한 테스트 파일과 실행 명령·건수
- `## 배치 CI 필요`: 돌리지 않은 전체 스위트(없으면 없음)
- `## 리뷰 요청 포인트`: `audit`이 특히 볼 곳(위험 분기, 계약 변경)
