# 역할 봇 지침

작업 카드 하나를 맡아 백그라운드에서 일하는 역할 세션(역할 봇)의 공통 규칙과 7종 목록이다.
역할 분담·작업 카드·품질 게이트·교차 리뷰의 정본은 `docs/claude-codex-collaboration.md`이고, 이 폴더는 그 규칙을 역할별 실행 지침으로 나눈 것이다.

## 역할 7종

| 역할 | 이름 | 기본 담당 | 입력 → 산출물 | 다음 단계 |
|---|---|---|---|---|
| `plan` | 기획 | Claude | 요청·intake 답변 → PRD, 개발계획, 카드 분해안 | `design`, `build` |
| `design` | 디자인 UI/UX | Claude | PRD·카드 → 화면 명세(텍스트) + HTML 와이어 | `build` |
| `build` | 개발 | Codex | 카드·PRD·화면 명세 → 코드, 단위 테스트, 커밋 | `audit` |
| `audit` | 오딧·검증 | 구현하지 않은 쪽 | 카드·diff → 리뷰 판정(중대 이슈 수) | `qa` 또는 `build`(수정) |
| `qa` | 기능 테스트 | Claude | 카드·diff → 단위·통합 테스트 추가와 실행 결과 | `scenario` |
| `scenario` | 시나리오 테스트 | Claude | 카드·화면 명세·실행 환경 → 브라우저 시나리오 결과, 스크린샷·로그 증거 | `docs` |
| `docs` | 매뉴얼 작성 | Claude | 완료 카드·화면·시나리오 증거 → 사용자·운영 매뉴얼 | 리드 보고 |

## 기본 파이프라인

```text
plan → design·build(병렬 가능) → audit → qa → scenario → docs
```

- `design`과 `build`는 화면 명세가 필요 없는 카드(서버·DB·API)일 때 병렬로 돈다. 화면 카드의 `build`는 `design` 산출물에 의존한다.
- `audit`에서 중대 이슈가 나오면 `build`로 돌아간다. 같은 지적의 자동 수정은 2회까지다(`docs/claude-codex-collaboration.md ## 자동 수정 반복 한도`).
- 카드에 필요 없는 단계는 리드가 건너뛴다(예: 문서만 바뀌는 카드는 `scenario` 생략). 건너뛴 단계와 이유는 리드가 결과 요약에 남긴다.

## 공통 규칙

- 시작하면 카드(`templates/task-card.md` 형식)의 목표·범위·완료 조건·의존 카드를 먼저 읽고, 이어서 프로젝트 `CLAUDE.md`·`AGENTS.md`·`docs/project-guide.md`(있으면)를 읽는다.
- 카드가 3단계 실행 승인을 대신한다. 카드 범위 밖 파일은 고치지 않는다(`docs/approval-workflow.md`).
- 일은 카드 전용 worktree(`<저장소이름>-worktrees/<카드ID>`)에서만 한다. 메인 체크아웃에 쓰지 않는다.
- 범위는 커밋까지다. push·PR·머지·배포·릴리스·원격 migration·강제 push·GitHub Actions 실행은 하지 않는다. PR은 리드가 만든다.
- `STATE.md`는 고치지 않는다. 여러 카드가 동시에 고치면 충돌하므로 리드가 모아 기록한다.
- 백그라운드라 사용자에게 물을 수 없다. 판단이 필요하면 추측으로 진행하지 않고 멈춘 뒤 결과 보고의 `남은 질문`에 적는다(`확인 필요`).
- 새 무거운 작업(개발 서버, 브라우저, Docker 빌드)은 메모리 사용률 80% 미만에서만 시작한다(`docs/claude-codex-collaboration.md ## 동시 실행과 메모리 한도`).
- 비밀값·`.env`·키 파일을 읽어 출력하거나 쓰지 않는다. 확인하지 않은 외부 의존성을 추가하지 않는다.

## 결과 보고 공통 형식

모든 역할은 마지막 응답을 아래 형식으로 끝낸다. 역할별 문서의 `## 결과 보고`가 항목을 더한다.

```text
## 결과
- 상태: 완료 | 확인 필요 | 실패
- 카드: <카드ID> / 역할: <역할> / 커밋: <해시 또는 없음>
## 바꾼 파일
- <경로> — <한 줄 요약>
## 검증 결과
- <명령> — <통과/실패, 건수>
## 남은 질문
- <사용자 결정이 필요한 것, 없으면 없음>
```

## 프로젝트 덮어쓰기

- 역할 세션은 `agents/roles/<역할>.md`를 먼저 읽는다. 프로젝트 루트에 같은 파일이 있으면 그것을, 없으면 `rules/agents/roles/<역할>.md`(공통 템플릿)를 읽는다. 공통본을 읽었으면 결과 보고에 한 줄로 밝힌다.
- 프로젝트 파일은 공통본 전체를 대체한다. 일부만 바꾸려면 공통본을 복사해 고친다.
- 산출물 위치·테스트 명령·담당 배분은 `docs/project-guide.md`가 이 폴더의 기본값보다 우선한다.

## agent-deck 설정과의 관계

- 역할 이름·켜기/끄기·담당은 프로젝트 `.agent-deck/config.toml`의 `[bots.<역할>]`(`provider = claude | codex | other`)이 정한다. 이 폴더는 담당을 정하지 않고, 역할이 무엇을 어떻게 하는지만 정한다.
- 위 표의 기본 담당은 agent-deck 기본 설정과 같다. 설정을 바꾸면 설정이 우선한다.
- 꺼진 역할의 카드는 리드가 만들지 않는다. `audit`을 끄면 리드는 결과 요약에 `교차 리뷰 생략(설정)`을 남긴다. 협업 규칙의 교차 리뷰 품질 게이트를 건너뛴 것이므로 사용자가 머지 전에 판단한다.
