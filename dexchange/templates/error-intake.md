# Error Handling Intake Template

## 글로벌 에러 처리
- Error Boundary 구성 방식 (전체 화면 에러 화면 vs 위젯 단위 에러 화면)
- 예상치 못한 치명적 에러 발생 시 Fallback UI 정책

## 사용자 알림 방식
- API 에러나 시스템 에러 시 사용자에게 어떻게 노출할 것인가? (토스트 알림, 모달창, 폼 내부 메시지)

## 로깅 전략
- 운영 서버 문제 추적을 위한 프론트엔드 에러 로깅 서비스 (Sentry, Datadog 등) 연동 계획

## 작성 예시

```
## 글로벌 에러 처리
- 라우트 레벨 Error Boundary로 페이지 단위 fallback.
- 위젯 단위는 자체 fallback UI를 가지며 다른 위젯에 영향 주지 않는다.
- 치명적 에러는 "잠시 후 다시 시도해주세요" 전체 화면 + 새로고침 버튼.

## 사용자 알림 방식
- API 4xx: 폼 내부 메시지 또는 인라인 에러 텍스트.
- API 5xx / 네트워크 오류: 토스트 알림 (3초 자동 닫힘, 재시도 액션 포함).
- 결제, 환불 등 치명적 흐름: 모달로 명시적 확인.

## 로깅 전략
- Sentry 사용. 운영 환경에서만 활성화.
- PII(이름, 연락처)는 scrubbing 후 전송.
- release 태그는 빌드 시 git SHA로 자동 주입.
```
