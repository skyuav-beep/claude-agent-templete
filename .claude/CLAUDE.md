# Claude 실행 게이트

Claude Code가 프로젝트 루트 `CLAUDE.md`와 함께 자동으로 읽는 파일이다.
공통 템플릿의 실행 절차를 런타임에 직접 주입하며, `.codex/README.md`가 Codex에서 하는 역할을 Claude에서 수행한다.

## 경로 규칙

`templates/`, `agents/`, `docs/`, `designs/`, `DESIGN.md`는 프로젝트 루트를 먼저 찾고, 없으면 `rules/` 아래 같은 경로를 읽는다.
프로젝트 로컬 파일이 항상 우선이며, 공통본을 대신 읽었으면 작업 보고에 한 줄로 밝힌다.

## 읽기 순서

1. 프로젝트 루트 `CLAUDE.md`와 `AGENTS.md`
2. `STATE.md`
3. `docs/project-guide.md`가 있으면 해당 문서와 현재 작업 영역의 하위 `AGENTS.md`
4. 작업 유형에 맞는 `agents/*.md`와 관련 `docs/*.md`
5. 작업 유형에 맞는 `.claude/skills/<name>/SKILL.md`

## 6단계 승인 절차

단순 사실 조회를 제외한 모든 분석·변경 작업에 적용한다. 정본은 `docs/approval-workflow.md`.

- 한 턴에는 한 단계만 진행한다.
- 1단계 요청 정리 — 목표, 산출물, 제약, 제외 범위를 정리한다. 응답 정책 부트스트랩 외에는 저장소 파일을 읽지 않는다.
- 2단계 읽기 전용 분석과 Git 계획 — 관련 문서·구현·git 상태를 읽고, 기준/작업 브랜치, worktree, 커밋·push 대상, PR head/base, 머지 방식, 머지 후 검증과 정리, 6단계 검증 범위를 적는다. 쓰기 작업은 하지 않는다.
- 3단계 실행 승인 — 정확한 실행 범위를 제시하고 명시적 승인을 기다린다.
- 4단계 구현 — 승인된 base에서 전용 worktree와 작업 브랜치를 만들고, 세션 승인 마커(`<메인 저장소>/.claude/.approval/<session_id>`)를 만든 뒤 승인 범위만 최소 변경한다.
- 5단계 읽기 전용 사후 감사 — diff 기준으로 누락·범위 이탈·회귀 위험·비밀값을 점검한다. 자동 수정하지 않는다.
- 6단계 빠른 검증과 Git 마무리 — 빠른 검증, `STATE.md` 기록, commit, push, ready PR, 게이트 확인, merge, 원격 base SHA 검증, 브랜치·worktree 정리를 순서대로 수행한다.

사용자의 메시지 전체가 공백 제거 후 `>` 하나이면 직전 응답의 `다음 단계 진행해`와 동일하게 해석한다. `>`만으로 push·merge·삭제·배포·원격 migration을 새로 승인하지 않는다.

3단계에서 전체 Git 수명주기를 승인받았으면 4~6단계의 `STATE.md` 기록과 Git 작업을 다시 묻지 않는다.
범위 확대, 보호 규칙 우회, 강제 push, 배포·릴리스, 원격 migration, 데이터 삭제는 승인 범위에 포함되지 않는다.

## 시작 전 확인

- 지금이 몇 단계인지, 3단계 승인을 받았는지 먼저 확인한다.
- `docs/project-guide.md`와 현재 작업 영역의 하위 `AGENTS.md`를 확인하고 프로젝트 기준을 템플릿 기본값보다 우선한다.
- 파일 삭제, 대규모 이동, 파괴적 명령, 비밀 파일 쓰기, 로컬 데이터 삭제, 배포·원격 migration은 사용자 확인 대상이다.

## 종료 전 확인

`docs/finish-checklist.md`를 적용한다.
문서나 운영 규칙을 바꿨으면 `STATE.md`를 갱신한다. 이는 3단계 승인에 포함된 사실 기록이므로 갱신 여부를 다시 묻지 않는다.
