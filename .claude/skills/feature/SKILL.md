# 기능 요청 구조화

신규 기능 요청을 대화형으로 구조화한다.

## 실행 방법

1. `templates/feature-request.md` 파일을 읽는다.
2. 템플릿의 섹션(목표, 배경, 원하는 산출물, 제약사항, 검증 기준)을 순서대로 질문한다.
3. 사용자 메시지에 기능 설명이 포함되어 있으면 가능한 항목을 먼저 채우고 부족한 부분만 추가 질문한다.
4. 모든 섹션이 채워지면 완성된 feature-request 마크다운 블록을 출력한다.

## 입력 처리

- 사용자 메시지에 기능 설명이 있으면 목표/배경을 미리 채운다.
- 설명이 부족하면 "어떤 기능을 추가하고 싶은지" 질문으로 시작한다.

## 진행 규칙

- 섹션별로 끊어서 자연스럽게 질문한다.
- 사용자가 간단히 답하면 그대로 반영하고 다음으로 넘어간다.
- 검증 기준은 반드시 수집한다.

## 완료 후

구조화된 feature-request 마크다운 블록을 출력하고, 바로 구현을 시작할지 사용자에게 확인한다. 구현·검증 단계는 `docs/local-dev-ci-guide.md`를 따른다 — 로컬 Docker Desktop 검증, 로컬 CI·push는 사용자 요청 시(CI는 GitHub Actions가 아니라 로컬 실행, §6.2).

## 다른 skill과의 연계

- 기능 설명에 UI/화면/스타일/컴포넌트/색·spacing·radius·typography 등 디자인 키워드가 포함되거나, 검증 기준에 시각적 기준(레이아웃·간격·다크 모드 대응 등)이 들어가면 `design` skill로 연계해 `DESIGN.md`를 1차 소스로 강제 로드한다.
- `templates/feature-request.md`의 `## 디자인 토큰 참조` 섹션이 채워졌는지 확인한다. 비어 있으면 design skill에서 토큰 호출 형식(`{group.name}`)으로 보강한다.
