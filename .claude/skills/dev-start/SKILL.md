# 개발 세션 부트스트랩

기존 프로젝트에서 개발을 재개할 때, 작업 상태 브리핑 → dev 컨테이너 기동 → hot reload·UI/로직 점검 준비를 순서대로 수행한다.

## 실행 방법

1. `docs/local-dev-ci-guide.md §2.0`(개발 세션 부트스트랩)을 읽는다. 절차의 정본이다.
2. 아래 3단계를 순서대로 수행한다.
   - 상태 브리핑: `STATE.md`의 `## 이번 세션에서 완료한 작업` + `## 다음 작업`을 읽고 직전 지점과 이어서 할 일을 한 줄로 요약한다.
   - dev 컨테이너 기동: `docker compose up -d`(항상, 멱등) → `docker compose ps` 확인 → `docker compose logs -f <svc>`로 watcher 기동(HMR/reload) 확인. 컨테이너 모델·폴링·재빌드 판단은 §2.1~§2.4.
   - UI/로직 점검 준비: 서비스 URL(`localhost:<port>`)과 (있으면) preview HTML 경로를 안내하고, 트리비얼 변경으로 hot reload 반영을 확인한다.
3. 점검이 끝나면 `STATE.md ## 다음 작업`부터 바로 개발을 이어간다.

## 입력 처리

- 사용자가 "개발 시작 / 이어서 개발 / 세션 시작 / 환경 셋팅해 / 다음 작업은" 류로 세션을 재개하면 활성화한다.
- 실제 명령·서비스명·포트는 프로젝트별 `AGENTS.md ### Operational Commands`에서 치환한다. 명령이 미정이면 사용자에게 확인한다.

## 진행 규칙

- 컨테이너 기동은 항상 `docker compose up -d`로 한다(상태 분기 없음 — 멱등이라 이미 기동 중이면 재생성하지 않는다). 세션 시작을 이유로 rebuild하지 않는다(§2.4 결정 트리).
- 모두 로컬 작업이라 agent 자동 실행 범위 안이다. 로컬 CI·push는 사용자 요청 시(CI는 로컬 실행, §1.1/§6.2).

## 우선순위

- "개발 시작"이 **무엇을 만들지**(기능/버그/로직)를 설명하는 맥락이면 `feature` / `bugfix` / `business-logic` skill을 우선한다. 본 skill은 **환경 부팅·상태 재개** 맥락에 한정한다.
