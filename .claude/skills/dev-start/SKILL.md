# 개발 세션 부트스트랩

기존 프로젝트에서 개발을 재개할 때, 작업 상태 브리핑 → dev 컨테이너 기동 → hot reload·UI/로직 점검 준비를 순서대로 수행한다.

## 실행 방법

1. `docs/local-dev-ci-guide.md`의 **개발 세션 부트스트랩** 절을 읽는다. 절차의 정본이다. 프로젝트가 자체 가이드를 두지 않았으면 공통 가이드(`rules/docs/local-dev-ci-guide.md §2.0`)를 쓴다. **섹션 번호가 아니라 절 이름으로 찾는다** — 프로젝트마다 번호 체계가 다르다.
2. 아래 3단계를 순서대로 수행한다.
   - 상태 브리핑: `STATE.md`의 최근 완료 사이클 + `## 다음 작업`을 읽고 직전 지점과 이어서 할 일을 한 줄로 요약한다.
   - dev 기동: 가이드의 부트스트랩 절이 지정한 compose 명령으로 기동(멱등) → 상태 확인 → 로그로 watcher(HMR/reload) 기동 확인. 기동 대상·컨테이너 모델·폴링·재빌드 판단은 가이드의 **개발 루프 / 재빌드** 절을 따른다. 가이드가 hot reload 대상에서 제외한 서비스(정적 빌드 serve 등)는 세션 기동 대상이 아니다.
   - UI/로직 점검 준비: 개발용 서비스 URL(hot reload가 걸린 포트)과 (있으면) preview HTML 경로를 안내하고, 트리비얼 변경으로 hot reload 반영을 확인한다.
3. 점검이 끝나면 `STATE.md ## 다음 작업`부터 바로 개발을 이어간다.

## 입력 처리

- 사용자가 "개발 시작 / 이어서 개발 / 세션 시작 / 환경 셋팅해 / 다음 작업은" 류로 세션을 재개하면 활성화한다.
- 실제 명령·서비스명·포트는 프로젝트별 `AGENTS.md ### Operational Commands`에서 치환한다. 명령이 미정이면 사용자에게 확인한다.

## 진행 규칙

- 컨테이너 기동은 상태 분기 없이 `up -d`로 한다(멱등 — 이미 기동 중이면 재생성하지 않는다). 세션 시작을 이유로 rebuild하지 않는다(판단은 가이드의 재빌드 결정 절).
- 예외: 이미지 빌드 산출물에 들어가는 코드(공유 패키지 dist, ORM 생성 클라이언트 등)를 고친 뒤의 첫 부팅이면, 컨테이너가 stale 산출물을 써서 부팅에 실패할 수 있다 → 그때만 해당 서비스를 증분 재빌드(`up -d --build <svc>`) 1회.
- 모두 로컬 작업이라 agent 자동 실행 범위 안이다. 로컬 CI·push는 사용자 요청 시(CI는 로컬 실행 — 가이드의 agent 실행 경계·로컬 CI 절).

## 우선순위

- "개발 시작"이 **무엇을 만들지**(기능/버그/로직)를 설명하는 맥락이면 `feature` / `bugfix` / `business-logic` skill을 우선한다. 본 skill은 **환경 부팅·상태 재개** 맥락에 한정한다.
