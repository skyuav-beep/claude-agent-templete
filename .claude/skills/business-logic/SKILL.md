# 비즈니스 로직 변경 요청 구조화

비즈니스 로직 변경 요청을 대화형으로 구조화한다.

> 경로 규칙: 아래 `templates/`·`agents/`·`docs/` 경로는 프로젝트 루트 기준이다. 프로젝트에 해당 파일이 없으면 `rules/` 아래 같은 경로를 읽는다(공통 템플릿을 `rules/` symlink로 연결한 프로젝트).

## 실행 방법

1. `templates/business-logic-request.md` 파일을 읽는다.
2. 템플릿의 7개 섹션을 순서대로 질문한다:
   - 변경 목표
   - 현재 문제
   - 요구사항 (입력 조건, 기대 결과, 제약, 제외 범위)
   - 시나리오 (정상, 실패, 경계값, 권한/상태별)
   - 영향 범위 (API, 화면, 서비스, 데이터 구조)
   - 검증 계획 (테스트, 빌드, Docker, 배포 전 확인)
   - Git 작업 계획
3. 사용자 메시지에 변경하려는 로직 설명이 있으면 가능한 항목을 먼저 채운다.
4. 모든 섹션이 채워지면 완성된 business-logic-request 마크다운 블록을 출력한다.

## 입력 처리

- 사용자 메시지에 변경 대상 설명이 포함되면 변경 목표를 미리 채운다.
- 설명이 부족하면 "어떤 비즈니스 로직을 바꾸려는지" 질문으로 시작한다.

## 진행 규칙

- 시나리오 섹션에서 정상/실패/경계값/권한별 시나리오를 반드시 수집한다.
- 사용자가 시나리오를 떠올리기 어려워하면 예시를 제시해서 유도한다.
- 영향 범위가 넓으면 단계별 진행을 제안한다.

## 완료 후

구조화된 business-logic-request 마크다운 블록을 1단계 산출물로 출력한다. 이후 `docs/approval-workflow.md`의 2단계 읽기 전용 분석과 3단계 승인을 거친 뒤 구현한다.
