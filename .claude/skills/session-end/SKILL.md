# 세션 종료와 인계 정리

세션을 닫기 전에 두 가지를 끝낸다. **기록**(이번에 무엇을 했고 다음에 무엇을 이어서 할지)과 **정리**(Git에 덜 끝난 것을 남기지 않기).

다음 세션이 `dev-start`로 재개할 때 `STATE.md`만 읽고 바로 이어갈 수 있는 상태를 만드는 것이 목표다.

> 경로 규칙: 아래 `templates/`·`agents/`·`docs/` 경로는 프로젝트 루트 기준이다. 프로젝트에 해당 파일이 없으면 `rules/` 아래 같은 경로를 읽는다(공통 템플릿을 `rules/` symlink로 연결한 프로젝트).

## 실행 방법

### 1. 작업 이력 수집 (읽기 전용)

이번 세션에서 무엇을 했는지 먼저 복원한다. 이 단계에서는 아무것도 바꾸지 않는다.

| 대상 | 확인 내용 |
|---|---|
| 작업 트리 | `git status --short --branch`, `git diff`, `git diff --staged` |
| 세션 커밋 | `STATE.md` 마지막 기록 이후 쌓인 커밋 |
| 진행 상태 | 완결된 작업과 손대다 만 작업의 구분 |
| 대화 맥락 | 이번 세션에서 내린 결정, 보류한 판단, 확인된 제약 |
| 기존 기록 | `STATE.md`의 마지막 세션 기록과 지금 사이의 공백 |

git 이력만으로는 "왜 그렇게 했는지"가 남지 않는다. 대화에서 나온 결정 근거와 시도했다가 접은 방향을 함께 수집한다.

### 2. 이력과 다음 작업 도출

수집한 내용을 두 갈래로 정리한다.

- **완료** — 무엇이 끝났고 어떤 근거로 그렇게 판단했는지. PR 번호·커밋 해시가 있으면 함께 적는다.
- **진행 중** — 어디까지 갔고 다음 한 수가 무엇인지. 다음 세션이 그대로 이어받을 수 있을 만큼 구체적으로 쓴다.
- **보류·미결** — 사용자 판단이 필요해 멈춘 것. 무엇을 물어야 하는지 남긴다.

진행 중 항목은 그대로 `## 다음 작업`의 재개 지점이 된다. "다음에 이어서 하기"로만 적지 않고 첫 행동을 적는다.

### 3. Git 전수 점검 (읽기 전용)

점검 항목은 `git-cleanup` 스킬과 같다. 여기서 다시 정의하지 않고 그 절차를 적용한다.

미커밋 변경, 미push 커밋, 열린 PR(draft·충돌·필수 검사), 머지 후 남은 로컬·원격 브랜치, 남은 worktree, `STATE.md` 미기록.

여러 세션이 같은 저장소를 쓰고 있으면 정리 전에 다른 세션의 점유를 확인한다. 다른 세션이 잡고 있는 브랜치·worktree는 정리 대상에서 빼고 사용자에게 알린다. 기준은 `docs/session-coordination-guide.md`.

### 4. 요약과 정리 계획 제시

먼저 **이번 세션에 무엇을 했는지**를 사용자 언어로 보여 준다. 파일 목록 나열로 대신하지 않는다. 그다음 정리 계획을 항목별로 제시하고, 판단이 갈리는 것은 선택지를 준다.

- 완결된 변경 → 커밋 대상으로 제안
- 미완성 변경 → 그대로 둘지, 별도 브랜치로 옮길지, WIP 커밋으로 남길지 확인
- 미push 커밋 → push + PR 생성 제안
- 열린 PR → 머지 가능하면 머지, 충돌·검사 실패면 이유와 함께 보류
- 머지 완료 브랜치·worktree → 삭제 제안
- 승인 마커 등 세션 로컬 산출물 → 삭제 제안

### 5. 승인 후 마감 실행

`docs/approval-workflow.md` 3단계 승인을 받은 뒤 6단계 순서대로 수행한다.

빠른 검증 → `STATE.md` 기록 → commit → push → ready PR → 게이트 확인 → merge → 원격 base SHA 검증 → 브랜치·worktree 정리.

`STATE.md` 갱신은 이미 수행한 작업의 사실 기록이므로 갱신 여부를 다시 묻지 않는다.

## STATE.md 기록 형식

프로젝트에 자체 형식이 있으면 그것을 따른다. 없으면 아래를 쓴다.

- `## 현재 상태` — `**세션 종료 (YYYY-MM-DD, 마지막)** — ` 로 시작하는 문단. 이번 세션의 성과, 판단 근거, 남은 리스크를 이어서 쓴다. 마지막에 미커밋·열린 PR·미완료 worktree 유무와 재개 지점을 밝힌다.
- `## 최근 완료 작업` — 완료 항목을 추가하고, 오래된 항목은 `docs/archive/`로 내린다.
- `## 다음 작업` — 재개 지점을 1순위에 둔다. 사용자 판단이 필요한 것은 별도 순위로 분리한다.

기존 기록을 덮어쓰기 전에, 그 내용이 아카이브로 옮겨야 할 것인지 확인한다.

## 완료 기준 (남기지 않는 것)

| 항목 | 종료 시점 기대 상태 |
|---|---|
| 미커밋 변경 | 없음. 남긴다면 사용자가 명시적으로 그렇게 결정한 것 |
| 미push 커밋 | 없음 |
| 열린 PR | 없음. 남긴다면 보류 사유가 `STATE.md`에 기록됨 |
| 잔여 브랜치 | 머지 완료 브랜치는 로컬·원격 모두 삭제 |
| 잔여 worktree | 작업용 worktree 삭제 후 `git worktree prune` |
| `STATE.md` | 이번 세션 이력과 다음 재개 지점이 기록됨 |

정리하지 못한 항목이 있으면 이유와 함께 최종 응답에 남긴다. 조용히 넘어가지 않는다.

## 입력 처리

- 대상을 지정하지 않으면 현재 저장소만 점검한다.
- 여러 저장소를 함께 정리하려면 사용자가 명시적으로 요청해야 한다. 요청받으면 저장소별로 구분해 보고한다.
- 기록만 원하거나 정리만 원하면 해당 부분만 수행한다.

## 우선순위

- Git 상태만 정리하는 맥락(`깃 정리`, `PR 정리`, `브랜치 정리`)은 `git-cleanup`을 쓴다. 본 skill은 **세션을 닫는 맥락**에서 기록과 정리를 함께 할 때 선택한다.
- 세션을 시작·재개하는 맥락은 `dev-start`다.

## 안전 경계

- **배포·릴리스 Action, `staging`/`production` migration은 실행하지 않는다.** 필요하면 명령을 알려 주고 사용자가 직접 실행한다.
- 강제 push, 보호 규칙 우회, 원격 base 강제 갱신은 하지 않는다.
- 만들다 만 변경을 임의로 되돌리거나 버리지 않는다. 지우는 것은 항상 확인을 받는다.
- 머지되지 않은 브랜치는 삭제 대상으로 제안하지 않는다.
- 로컬 dev 컨테이너·DB 볼륨은 세션 종료를 이유로 삭제하지 않는다.

## 산출물

- 이번 세션 작업 이력 요약 (완료 / 진행 중 / 보류)
- 다음 세션 재개 지점
- 정리 계획과 사용자 확인이 필요한 선택지
- 실행 결과: 커밋 해시, PR 번호, 머지 SHA, 정리된 브랜치·worktree
- 정리하지 못한 항목과 그 이유
