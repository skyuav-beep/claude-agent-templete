# 미완료 Git 작업 점검과 정리

작업하다 만 변경, 커밋만 하고 두고 온 브랜치, 열어 두고 잊은 PR, 머지 후 남은 브랜치·worktree를 한 번에 찾아 마무리한다.

> 경로 규칙: 아래 `templates/`·`agents/`·`docs/` 경로는 프로젝트 루트 기준이다. 프로젝트에 해당 파일이 없으면 `rules/` 아래 같은 경로를 읽는다.

## 실행 방법

1. **점검(읽기 전용)** — 미커밋 변경, 미push 커밋, 열린 PR(draft·충돌·검사), 머지 완료 후 남은 브랜치·worktree, `STATE.md` 미기록을 확인한다.
2. **개발 내용 먼저 요약** — 파일 목록만 나열하지 말고 변경 내용을 읽어 어떤 작업이 어디까지 진행됐는지 설명한다. 커밋 가능한 완결 변경과 미완성 변경을 구분한다.
3. **정리 계획 제시** — 항목별 처리 방안과 판단이 갈리는 선택지를 함께 제시한다.
4. **승인 후 실행** — `docs/approval-workflow.md` 3단계 승인 후 6단계 순서대로: 빠른 검증 → `STATE.md` 기록 → commit → push → ready PR → 게이트 확인 → merge → 원격 base SHA 검증 → 브랜치·worktree 정리.

## 인수 처리

- 인수가 없으면 현재 저장소 전체를 점검한다.
- 브랜치명이나 PR 번호를 주면 그 항목만 다룬다.
- 다른 저장소는 사용자가 명시적으로 요청할 때만 점검하고, 저장소별로 구분해 보고한다.

## 안전 경계

- **배포·릴리스 Action과 `staging`/`production` migration은 실행하지 않는다.** 명령을 알려 주고 사용자가 직접 실행한다.
- 강제 push, 보호 규칙 우회는 하지 않는다.
- 만들다 만 변경을 임의로 되돌리거나 버리지 않는다. 삭제는 항상 확인을 받는다.
- 머지되지 않은 브랜치는 삭제 대상으로 제안하지 않는다.
