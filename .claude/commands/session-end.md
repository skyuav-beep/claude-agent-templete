# 세션 종료와 인계 정리

세션을 닫기 전에 이번에 한 작업과 다음 재개 지점을 `STATE.md`에 남기고, Git에 덜 끝난 것을 남기지 않는다.

> 경로 규칙: 아래 `templates/`·`agents/`·`docs/` 경로는 프로젝트 루트 기준이다. 프로젝트에 해당 파일이 없으면 `rules/` 아래 같은 경로를 읽는다.

## 실행 방법

1. **작업 이력 수집(읽기 전용)** — `git status`, diff, 마지막 `STATE.md` 기록 이후의 커밋을 읽는다. 대화에서 나온 결정 근거와 접은 방향도 함께 모은다. git 이력만으로는 "왜"가 남지 않는다.
2. **이력과 다음 작업 도출** — 완료 / 진행 중 / 보류로 나눈다. 진행 중 항목은 다음 세션의 첫 행동까지 구체적으로 적는다.
3. **Git 전수 점검(읽기 전용)** — 미커밋 변경, 미push 커밋, 열린 PR(draft·충돌·검사), 머지 후 남은 브랜치·worktree, 세션 로컬 산출물. 점검 항목은 `/git-cleanup`과 같다.
4. **요약과 정리 계획 제시** — 무엇을 했는지 사용자 언어로 먼저 보여 주고, 항목별 처리 방안과 선택지를 함께 제시한다.
5. **승인 후 마감** — `docs/approval-workflow.md` 3단계 승인 후 6단계 순서대로: 빠른 검증 → `STATE.md` 기록 → commit → push → ready PR → 게이트 확인 → merge → 원격 base SHA 검증 → 브랜치·worktree 정리.

## 인수 처리

- 인수가 없으면 기록과 정리를 모두 수행한다.
- `state` — `STATE.md` 기록만 수행한다.
- `git` — Git 점검·정리만 수행한다.
- 다른 저장소는 사용자가 명시적으로 요청할 때만 다루고, 저장소별로 구분해 보고한다.

## 완료 기준

미커밋 변경·미push 커밋·잔여 브랜치·잔여 worktree를 남기지 않는다. 열린 PR을 남긴다면 보류 사유를 `STATE.md`에 기록한다. 정리하지 못한 항목은 이유와 함께 최종 응답에 남긴다.

## 안전 경계

- **배포·릴리스 Action과 `staging`/`production` migration은 실행하지 않는다.** 명령을 알려 주고 사용자가 직접 실행한다.
- 강제 push, 보호 규칙 우회는 하지 않는다.
- 만들다 만 변경을 임의로 되돌리거나 버리지 않는다. 삭제는 항상 확인을 받는다.
- 머지되지 않은 브랜치는 삭제 대상으로 제안하지 않는다.
- 로컬 dev 컨테이너·DB 볼륨은 세션 종료를 이유로 삭제하지 않는다.
