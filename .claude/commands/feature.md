# 기능 요청 구조화

신규 기능 요청을 대화형으로 구조화한다.

> 경로 규칙: 아래 `templates/`·`agents/`·`docs/` 경로는 프로젝트 루트 기준이다. 프로젝트에 해당 파일이 없으면 `rules/` 아래 같은 경로를 읽는다(공통 템플릿을 `rules/` symlink로 연결한 프로젝트).

## 실행 방법

1. `templates/feature-request.md` 파일을 읽는다.
2. 템플릿의 섹션(목표, 배경, 원하는 산출물, 제약사항, 검증 기준)을 순서대로 질문한다.
3. `$ARGUMENTS`가 있으면 사용자 입력에서 가능한 항목을 먼저 채우고 부족한 부분만 추가 질문한다.
4. 모든 섹션이 채워지면 완성된 feature-request 마크다운 블록을 출력한다.

## 인수 처리

- `$ARGUMENTS`가 있으면 기능 설명으로 간주하고 목표/배경을 미리 채운다.
- `$ARGUMENTS`가 비어 있으면 "어떤 기능을 추가하고 싶은지" 질문으로 시작한다.

## 진행 규칙

- 섹션별로 끊어서 자연스럽게 질문한다.
- 사용자가 간단히 답하면 그대로 반영하고 다음으로 넘어간다.
- 검증 기준은 반드시 수집한다.

## 완료 후

구조화된 feature-request 마크다운 블록을 1단계 산출물로 출력하고 `docs/approval-workflow.md`의 2단계부터 진행한다.

## 승인 절차 연결

- 이 흐름의 산출물은 `docs/approval-workflow.md` 1단계에 해당한다. 한 턴에는 한 단계만 진행한다.
- 이후 2단계 읽기 전용 분석과 Git 계획, 3단계 실행 승인, 4단계 구현, 5단계 읽기 전용 사후 감사, 6단계 빠른 검증과 `STATE.md` 기록·Git 마무리로 이어간다.
- 시작·종료 게이트는 `.claude/CLAUDE.md`, 종료 확인 목록은 `docs/finish-checklist.md`를 적용한다.
